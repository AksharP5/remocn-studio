# Export readiness: contract, measurements and verification

## Calling the tool

Existing `design_check({frames:[30,90], motion, video})` calls retain the sampled
path. Before export, use `design_check({mode:"full", video, options})`; `frames`
is not required. The richer result is in `readiness`; the legacy top-level
snapshot/finding shape remains available. Source tunability has its own audience
and check status, separate from viewer defects.

Example options:

```json
{
  "maxFrames": 360,
  "maxDurationMs": 180000,
  "language": "ru",
  "platform": "reels",
  "audio": {
    "expected": true,
    "speechIntervals": [{"from": 30, "to": 150}],
    "stems": [
      {"role": "speech", "inputProps": {"music": false, "voice": true}},
      {"role": "music", "inputProps": {"music": true, "voice": false}}
    ]
  }
}
```

Stem props must actually isolate those roles in the authored composition. The
checker does not rewrite source `volume` expressions to manufacture stems. It
renders each supplied configuration through Remotion and rejects timeline changes.
All audio intervals and exceptions use composition frames, from inclusive and to
exclusive. Missing role stems or speech intervals mean masking is skipped with a
reason; they never mean that speech is proven intelligible.

`mode:"report", reportId:"<id>"` reloads retained evidence and recomputes staleness.
Supply current options to also compare runtime props/export identity. A full
recheck always measures again across the composition, including scenes sharing a
changed component. Exceptions require code, selector (nullable), from/to, reason,
and the previous report revision. Relevant revision changes invalidate them.

The host/MCP protocol forwards progress, cancellation and disconnects. A cancelled
run retains completed frame evidence and its partial report in the preview cache.
Reports are stored in separate `readiness-<id>` directories; running another check
does not remove the preceding report. There is no automatic repair loop or export
block driven by stylistic recommendations.

## Sampling and confidence

The base plan reserves 75% of the frame budget for distributed coverage: first and
last frame, each scene midpoint, and neighboring frames around every start/end.
The fallback without a scene map is a uniform grid, explicitly marked as reduced
coverage. Default temporal spacing is about 250 ms. Findings, changed frames and
near-black samples add local neighbors/midpoints until the total budget is reached.
A missing assertion sample is unverified, not a missing DOM target.

`coverage.complete` means the planned pass finished, not that every video frame
was analyzed. `exhaustive`, `sampled`, `unmeasuredIntervals`, failed frames and
limitations make this distinction explicit. Time/frame exhaustion and render
failures cannot produce complete coverage. Each check independently reports
completed, not applicable, skipped or failed, with a reason. Execution status is
independent of defect severity. Large temporal gaps skip reading-window inference
instead of interpreting isolated snapshots as short-lived text.

## Measurements

- Text geometry, clipping and occlusion reuse the existing browser audit. Entirely
  offscreen text is also tracked. A measured text/contrast defect held for at least
  0.5 seconds across adjacent samples becomes an error; transient entry/exit
  findings remain informational. Disjoint occurrences receive separate identities.
- Contrast uses rendered background pixels with text paint temporarily removed,
  then restores the original styles. CSS colors, including OKLCH, are converted by
  the browser to screenshot sRGB. Foreground opacity is included. Thresholds are
  4.5:1 or 3:1 for large text, as measurement guidance, not accessibility certification.
  Transparent backgrounds and unsupported blended/gradient text are explicitly
  unknown; Canvas/video text is not silently claimed as inspected DOM text.
- Reading time defaults to 180 words/minute plus 0.5 seconds; CJK uses 8 characters
  per second plus the same lead. Language, speeds, lead and readable opacity
  (default 0.8) are configurable. Word/letter spans contribute text only as they
  become readable. Time behind occlusion, clipping, or outside the frame does not
  count. An uninterrupted text lifetime can cross a scene boundary. Use
  `data-reading-id` for an explicit reading group.
- Text safe zones are automatic. Tag non-text logos/CTAs with
  `data-design-role="logo"` or `"cta"`; subtitles can use `"subtitle"`. Untagged
  raster semantics cannot be inferred. Insets are composition pixels; explicit
  insets override a platform guide. No platform means not applicable, while
  composition bounds remain active.
- Image/media decode failures, FontFace load errors and a mismatch against
  `data-expected-font` provide resource diagnostics. Computed CSS alone cannot
  confirm per-glyph fallback; that limitation is reported. Frame errors retain
  the original reason and their frame/scene, alongside successful inspections.
- Existing motion assertions and rhythm/continuity/camera measurements are reused.
  Black intervals require visible evidence on both sides; static holds and camera
  choices remain intent recommendations. No missing-resource claim is derived
  solely from black pixels.
- Audio is actual Remotion WAV mixdown, including Sequence boundaries, trim,
  playback rate and volume functions. PCM is streamed in bounded chunks into
  10 ms RMS/peak windows. Repeated full-scale samples indicate clipping risk;
  peak headroom defaults to -1 dBFS, silence to -55 dBFS, and speech/backing
  margin to 6 dB. Abrupt audible boundaries are recommendations; declared speech
  intervals improve attribution without claiming a particular word was cut.
  Planned pauses and intentionally silent video are valid. Role stems allow a
  disappearing speech tail to be measured even when the full mix still contains
  music. Intersample true peaks and semantic transcription are not measured.

## Profile provenance, reviewed 2026-09-09

- TikTok: [official In-Feed specification](https://ads.tiktok.com/resources/help/article/tiktok-auction-in-feed-ads)
  and its [standard LTR template archive](https://lf-tt4b.tiktokcdn.com/obj/i18nblog/tt4b_cms/en-US/5jqet0ab9qci-10e7f5Vig4uhAscNP8XPB0.zip).
  The 720×1280 diagram has top 160, bottom 440 and side 80 px exclusions, plus
  a lower-right 120 px exclusion. The rectangular guide conservatively uses
  left 80/right 200/top 160/bottom 440. Anchor, RTL and caption variants differ.
- YouTube Shorts: [Google's universal video safe-zone diagram](https://services.google.com/fh/files/misc/universalsafezones-youtube.pdf),
  vertical 1080×1920: left 48/right 192/top 288/bottom 672 px.
- Instagram Reels: bottom 35% is documented in [Meta's Reels creative guide](https://d3m889aznlr23d.cloudfront.net/img/events/458925814/assets/e042d2be.reels_ads_guide1.pdf).
  The preset uses top 14% and 6% sides as guidance margins. The current Meta
  placement page redirected to login during verification, so those margins are
  not represented as newly verified live UI dimensions. The report records this
  qualification; custom insets support an exact placement preview.

Platform guides scale with composition dimensions and remain recommendations,
not guarantees for every device/caption/ad placement. A platform is always chosen
explicitly. For another format or UI variant, use explicit pixel insets.

## Revision and resource limits

The revision hashes project file contents plus composition, scene/motion context,
props, analysis options and renderer configuration. Hashing is streaming and
canonicalizes object keys. Generated output/dependencies/VCS directories are
excluded. Source/asset changes during a run mark the report stale and remove
exception applicability. Symlink targets and mutable remote resources are not
pinned and are disclosed as limitations. `exportSettings` records downstream
export identity; it does not change composition layout or replace the export tool.
Measurements use resolved composition props and the project's Chromium settings.

Memory telemetry in the report is the host process RSS, excluding Chromium and
encoder subprocesses. It must not be presented as total render-process memory.
Audio rendering limits concurrency to two. Time cancellation waits for in-flight
renderer cleanup rather than leaving an encoder writing an orphaned output.

## Reproduction

Fast checks: `bun test sidecar/preview sidecar/tools shared/pipeline.test.ts`.
The renderer suite is `scripts/readiness-smoke.ts`. Set
`REMOCN_READINESS_TEST_PROJECT` to an existing project containing matching
`@remotion/bundler`, `@remotion/renderer`, React and Remotion packages, then run
`bun scripts/readiness-smoke.ts`. It creates its own temporary fixture, uses that
project's dependencies read-only, and retains reports/PNGs/WAVs for inspection.
The fixture and defective/fixed variants live in
`scripts/fixtures/readiness.tsx.txt`. Real Chromium requires normal macOS process
launch permissions; a restricted shell may not be able to launch it.
