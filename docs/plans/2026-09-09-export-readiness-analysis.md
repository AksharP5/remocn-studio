# Export readiness: аудит REM-5

Дата: 2026-09-09. Задача: https://linear.app/remocn/issue/REM-5

## Вывод

Основа экспорта существует, но инвариант «экспорт соответствует preview» пока не обеспечен. Добавления диалога недостаточно: нужны общий контекст композиции, надёжная подготовка Chromium, фиксация входов рендера и настоящие интеграционные проверки.

Ошибка WebGL2 воспроизведена через текущий preview host на минимальной сцене. При отсутствии явного GL backend canvas.getContext("webgl2") вернул null. Единственное изменение — Config.setChromiumOpenGlRenderer("angle") — позволило экспортировать корректную анимацию. Это подтверждает конкретную причину на проверенной конфигурации, но не заменяет проверку пользовательского проекта и других GPU.

Изменения приложения в рамках аудита не вносились.

## Как устроены preview и export

1. sidecar/preview/host.ts запускает webpack watch для проекта с установленными в нём пакетами Remotion. Настройки bundler находятся в sidecar/preview/bundling.ts.
2. preview/entry.tsx содержит приложение preview с Remotion Player и импортирует renderEntry. Preview отображается в WebKit webview приложения.
3. sidecar/preview/server.ts обслуживает страницу preview и отдельную render-страницу из той же сборки.
4. Экспорт использует собственный Chrome Headless Shell через @remotion/renderer проекта. readyBrowser подготавливает браузер, warmComposition/selectComposition получает композицию, renderMedia кодирует файл.
5. Preview может использовать медиапрокси. Render-маршрут намеренно получает оригиналы ресурсов — это правильное поведение.
6. sidecar/preview/export.ts сейчас жёстко задаёт H.264, MP4, исходный размер и out/<composition>.mp4. Есть прогресс, отмена, временный файл рядом с результатом, rename после успеха и открытие результата в Finder.
7. Блокировка энкодера в host разделяется между export и clip. Это не доказательство глобальной блокировки всех хостов/проектов.
8. Snapshot, clip и design_check используют родственные пути Chromium. Политика браузера должна быть общей.

Одинаковая сборка не означает одинаковую среду: WebKit/Player и Chromium/frame rendering отличаются поддержкой GPU, медиа, шрифтов и жизненным циклом кадров.

## Что подтверждено исполнением

### WebGL

Среда: macOS arm64; Remotion 4.0.520; 320×180, 30 fps, 6 кадров. Компонент создаёт WebGL2-контекст и меняет цвет по useCurrentFrame.

- Без заданного backend: export-failed, AUDIT_WEBGL2_UNAVAILABLE: canvas.getContext(webgl2) returned null.
- С angle: H.264 MP4, 6 кадров, 320×180, 13 443 байта.
- Декодированные средние RGB по кадрам: [0,126,65], [44,127,65], [86,128,64], [129,128,65], [169,127,64], [213,127,65]. Изображение не просто существует: кадры меняются.
- Повторный запуск с angle: export, still, clip и design_check успешно завершились. Design-check выбрал кадры 0, 3, 5, findings пуст.
- Это небольшая WebGL2-сцена, а не проверка Three.js, WebGPU, сложных шейдеров, GPU memory pressure или конкретного проекта пользователя.

Remotion рекомендует angle для desktop WebGL. В Remotion 4 стандартное значение gl — null; нельзя полагаться на дефолт другой основной версии. Документация: https://www.remotion.dev/docs/gl-options

### Конфигурация

Проба вызвала существующий renderOptionsOf дважды в одном процессе:

1. Config: angle, CRF 12, concurrency 1.
2. Изменённый config: swangle, CRF 28, concurrency 2.

Во второй результат снова попал angle. Полей CRF и concurrency нет в обоих результатах.

Причины в sidecar/preview/project.ts:

- loadConfig импортирует один и тот же URL, повторный вызов использует module cache.
- RenderOptions извлекает только chromeMode, chromiumOptions и timeout.
- Ошибки чтения внутренних Remotion options превращаются в null; источник значения теряется.
- renderMedia вызывается программно, поэтому отсутствие аргумента не означает автоматическое применение соответствующей CLI Config-настройки.

Документация: https://www.remotion.dev/docs/config и https://www.remotion.dev/docs/renderer/render-media

### Существующие тесты

Запущено:

    bun test sidecar/preview/export.test.ts sidecar/preview/project.test.ts sidecar/preview/still.test.ts hooks/use-export.test.tsx lib/studio/export.test.ts

Результат: 80 pass, 0 fail, 137 expect. Renderer в этих тестах подменён, поэтому зелёный результат не выявил реальную проблему WebGL.

Временная воспроизводящая среда: /private/tmp/remocn-export-audit-ExlgOO. Артефакты: baseline-result.json, result.json, suite-result.json, config-result.json, out/WebGLProbe.mp4. probe.ts запускает настоящий runPreviewHost из приложения. Команда:

    AUDIT_SUITE=1 bun /private/tmp/remocn-export-audit-ExlgOO/probe.ts

Запуск Chrome требует среды, где ему разрешено запускать дочерние процессы. Первоначальный запрет macOS sandbox был отдельной проблемой среды аудита; вывод о WebGL получен после успешного запуска Chromium.

## Пробелы, установленные чтением кода

### Метаданные композиции и props

preview/entry.tsx, measured(), читает статические width/height/fps/durationInFrames и использует defaultProps. calculateMetadata здесь не исполняется. Export через selectComposition получает рассчитанные metadata и props.

Следствия: композиция с вычисляемыми размерами/длительностью может не открыться в preview либо экспортироваться с другими параметрами. Результирующие composition.props renderer использует — проблема не в потере этих props внутри renderMedia, а в разных путях их получения.

Сообщение describe из preview не передаёт приложению полный набор разрешённых метаданных, нужный для расчёта выходного разрешения.

### Несохранённые изменения

Inspect/tuning может менять только runtime preview. hooks/use-inspect.ts отправляет tune.set; запись исходников — отдельный асинхронный путь hooks/use-code-writes.ts.

hooks/use-tools.ts передаёт useExport composition и serving-state, но не состояние незаписанных правок/очереди записи/ревизию сборки. Export способен отрендерить исходник без показанных в preview изменений.

### Изменения проекта во время рендера

Сборка обслуживается живым webpack watch; при rebuild сбрасываются кэши и warm session. Export не получает отдельного неизменяемого набора bundle/assets. Новый код или заменённый ресурс может попасть в ещё открываемые render pages текущего задания.

Нужен стабильный набор входов на всё задание. Одной блокировки кнопки Export недостаточно: файлы может менять агент или внешний редактор.

### Диагностика и жизненный цикл

sidecar/preview/still.ts, renderError(), интерпретирует любой текст с delayRender() как отсутствие WebGL. Так же могут выглядеть зависшие шрифты, сеть, видео и другие причины. Нужна классификация с сохранением первичной ошибки.

CancelSignal создаётся непосредственно у renderMedia; скачивание браузера и измерение композиции происходят раньше. Проверить отмену всех стадий, освобождение browser/page/server при ошибках warm-up, завершение encoder перед удалением partial и закрытие проекта. Эти риски обнаружены по коду; аварийные сценарии исполнением ещё не проверены.

### Диалог и форматы

Пока отсутствуют: выбор формата/качества/разрешения, Save dialog, запоминание параметров, presets, проверки совместимости codec/quality/pixel format/размеров. В Tauri разрешён dialog:allow-open, разрешения allow-save нет.

## Предлагаемая реализация одной поставкой

Последовательность ниже — порядок работ, не разделение на версии.

### 1. Общий контекст композиции и готовность к экспорту

Ввести явные revision, compositionId, inputProps, resolvedProps, width, height, fps и durationInFrames. Preview и export получают согласованный результат calculateMetadata для одной ревизии.

Перед запуском: завершить принятые записи Inspect, дождаться успешной сборки и обновлённых metadata. Если временные правки невозможно автоматически сохранить — показать конкретный выбор сохранить/отменить правки; не экспортировать молча старый вариант. Ошибки записи или компиляции останавливают старт с объяснением.

### 2. Настройки рендера и поддержка версий

Сделать адаптер конфигурации проекта с сохранением источника значений. Разрешать только поддерживаемые опции установленной версии, не скрывать несовместимость внутренних API.

Порядок разрешения совместимых полей: явный выбор export → явно настроенное значение проекта → metadata композиции для соответствующих полей → объявленный дефолт renderer/Studio. Нельзя переносить несовместимые CRF, bitrate, ProRes profile между кодеками.

Project default должен действительно читать и передавать поддерживаемые настройки; нельзя объяснять его как «ничего не передаём и получаем CLI parity». Документировать набор поддерживаемых настроек и явно сообщать об ограничениях. Как минимум покрыть codec/quality, browser executable/mode/GL, timeout, concurrency, inputProps/env, scale, audio/pixel-format/color-space настройки, влияющие на поддерживаемые форматы.

Изменение remotion.config и его зависимостей должно обновлять конфигурацию без stale singleton/module cache; надёжный вариант — перезапуск соответствующего host/config worker с очисткой связанных кэшей.

### 3. Общая политика Chromium и GPU

Один resolver/launcher для export, still, clip, design_check и других renderer-backed операций.

- Сохранять явную настройку gl пользователя.
- Для автоматического desktop режима выбрать angle и проверять реальные WebGL/WebGL2 capabilities того же браузера, которым будет рендер.
- Software fallback, например swangle, разрешать только после проверки поддержки данной версии/платформы. Не подменять им явно выбранный backend и не перезапускать произвольно любую упавшую сцену.
- Показывать выбранный backend и причину fallback в диагностике; подобрать ограниченный concurrency с учётом GPU/памяти.
- Различать context unavailable, context lost/OOM, JavaScript error, missing asset, media decode и delayRender timeout. Увеличение timeout не исправляет отсутствие WebGL.
- WebGPU и специфические расширения проверять отдельно. Наличие WebGL2 не гарантирует их поддержку.

### 4. Стабильное задание рендера

Создавать RenderJob с фиксированными настройками, metadata/props и ревизией bundle/assets. Рендер обслуживать из неизменяемой сборки; локальные входные ресурсы закреплять на время задания, не читать меняющиеся оригиналы.

Внешние URL и недетерминированный код требуют явного контракта: загрузка/фиксация ресурсов, либо понятная ошибка или объявленное ограничение. Нельзя обещать побитовое совпадение для произвольного Date.now(), Math.random(), requestAnimationFrame или изменяющегося удалённого API.

Состояния задания: preparing → rendering → finalizing → done/failed/cancelled. Отмена и освобождение ресурсов работают на каждой стадии. Не разрешать новый конфликтующий encoder, пока предыдущий действительно не завершился.

### 5. Диалог экспорта

Сохранить основную продуктовую модель REM-5:

- Format: MP4/H.264, WebM/VP9, GIF, MOV/ProRes.
- Quality: Project default, Draft, Standard, High; codec-specific CRF или ProRes proxy/standard/hq. Для GIF качество скрыто, отсутствие аудио явно обозначено.
- Resolution: Source, короткая сторона 720/1080/2160 px. Показывать точные выходные width×height; проверить масштаб и ограничения выравнивания пикселей кодека, не менять layout сцены. При невозможности точного сочетания — понятная валидация/совместимый размер без скрытого crop.
- Presets: YouTube 16:9; Shorts/TikTok/Reels 9:16; Instagram Feed 1:1 или 4:5. H.264, короткая сторона 1080, High. Это удобные стартовые параметры, а не гарантия соблюдения всех ограничений платформ.
- Preset заполняет поля; ручное изменение переводит в Custom.
- Несоответствие aspect ratio — предупреждение; export не перестраивает композицию, не добавляет crop/letterbox. Upscale разрешён с предупреждением о растровых ресурсах.
- Native Save dialog с подходящим расширением и overwrite prompt; добавить dialog:allow-save. Имя <Composition>-<preset>.<ext> или <Composition>.<ext>.
- Запоминать выбор и папку по стабильному projectId; начальная папка out/. Согласовать хранение с проектной сущностью REM-263. Локальный абсолютный путь последнего сохранения — предпочтение устройства, не переносимый бренд/project asset.
- Partial располагается рядом с целевым файлом; только успешное завершение заменяет результат. При сбое предыдущий файл остаётся.
- Обновить типизированный IPC и версию протокола, UI прогресса/отмены/повторного запуска/Finder.

### 6. Проверки перед экспортом и тесты

Техническая готовность к запуску относится к REM-5. Полный анализ дизайна и аудио относится к REM-377. Чистый результат design_check не доказывает готовность каждого кадра к кодированию.

| Сценарий | Проверка |
| --- | --- |
| DOM/SVG/Canvas2D, текст и локальные/веб-шрифты | реальные кадры, загрузка шрифтов, отсутствие пустых кадров |
| WebGL1/WebGL2, Three.js/shaders | auto/explicit backend, меняющиеся кадры, context failure, нагрузка |
| calculateMetadata и inputProps | одинаковые props, размеры, fps, длительность в preview и export |
| Inspect и agent writes | сохранение/ошибка записи/rebuild перед стартом, отсутствие старых стилей |
| H.264/VP9/GIF/ProRes | настоящий output, codec, контейнер, размеры, длительность; звук там, где поддержан |
| Video/OffthreadVideo, прозрачные изображения, GIF | trim, loop, границы Sequence, синхронизация кадров |
| Audio/несколько дорожек | длительность, громкость, trim, fades, mute, рассинхронизация; GIF без аудио |
| Локальные/удалённые ресурсы | пути с пробелами/Unicode, отсутствие файла, offline, HTTP range/CORS |
| Длинная/4K/вертикальная композиция | память, GPU concurrency, upscale, нечётные исходные размеры |
| Изменение файлов во время рендера | стабильная ревизия всех кадров |
| Save/cancel/failure | отмена каждой стадии, место на диске/права, старый файл сохранён, partial очищен |
| Повторный экспорт/смена проекта | нет stale job/progress/config, ресурсы освобождены |

Оставить быстрые unit/hook тесты, но дополнить реальными browser/renderer smoke fixtures. Как минимум воспроизведение WebGL должно краснеть без исправления и проверять содержимое кадров после исправления. Для кодеков использовать media probe/декодирование, для звука — небольшой известный аудиосигнал и проверку тайминга. Не ограничиваться успешным Promise и существованием файла.

Гарантировать согласованные входы и корректные кадры на поддержанных конфигурациях. Побитовое равенство WebKit preview и Chromium не является реалистичным универсальным критерием; визуальные сравнения требуют допусков для растеризации текста/GPU.

## Границы

В одну поставку входят надёжность базового рендера и весь описанный диалог. Очередь, выбор диапазона, редактор собственных presets, отдельные audio knobs, alpha export/ProRes4444, PNG sequence, H.265 и cloud rendering остаются за рамками REM-5.

Временный обход для воспроизведённого WebGL случая: добавить Config.setChromiumOpenGlRenderer("angle") в remotion.config.ts и перезапустить preview host/проект, чтобы обойти кеш конфигурации. Это не закрывает остальные найденные пробелы.
