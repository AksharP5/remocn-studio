# Промпт для следующего эксперимента

Предложенный brief для нового теста, а не описание уже заказанного пользователем ролика. Он предназначен для работы после замены конфликтующих runtime-правил. Пользовательский промпт сам по себе не гарантирует отмену более приоритетных требований Studio.

---

Создай продуктовый ролик Remocn Studio длительностью 20–25 секунд, 1920×1080. Сначала сделай проверочный фрагмент 6–8 секунд с самым сложным действием и переходом, оцени его и только после этого развивай полный ролик.

Главное обещание: из запроса получается видео, которое можно точно поправить прямо в интерфейсе. Покажи один конкретный результат и одно изменение этого же результата. Используй реальные состояния продукта; текст запроса и изменение должны соответствовать доступным возможностям.

Не требуется повторять чужую геометрию слайдера.

Для этого эксперимента выбери спокойное продуктовое направление: Manrope Regular как исходное предпочтение, один главный объект в каждый момент, осмысленная крупность UI. Палитру и продуктовые компоненты возьми из текущего Remocn Studio. Добавляй фоновые детали только если они необходимы выбранной композиции; исходный вариант может обходиться без них.

До полной анимации:

1. Изучи референсы и доступные реальные состояния интерфейса. Запиши одним абзацем, какие решения переносишь и какие assets используешь.
2. Сделай три ключевых кадра: ввод запроса, готовый результат, результат после точной правки. Покажи тот же пример, чтобы зритель мог увидеть разницу.
3. Выбери самый сложный участок — действие пользователя, перестройку интерфейса и появление результата — для проверочного фрагмента.

Построй события в таком порядке: зритель видит цель → курсор приходит к ней → действие срабатывает → интерфейс заметно отвечает → камера помогает рассмотреть ответ → результат остаётся достаточно долго, чтобы понять изменение. Длительности выбери по читаемости и референсу. Если объект превращается в другой, сохрани его положение и геометрию в момент передачи; проверь соседние кадры на скачки и дубли.

Сначала выбери композицию и связь событий, затем подбери easing. Завершённые элементы могут оставаться неподвижными. Смена сцены может быть склейкой, если она понятна. Сильный переход нужен там, где он связывает смысл, а не между каждой парой фраз.

Просмотри проверочный фрагмент в движении и сопоставь с Paper: понятно ли без сценария, что сделали и что изменилось; виден ли клик; достаточно ли крупный результат; есть ли время его увидеть. Исправь эти вещи до сборки остальных секунд. Обычные решения принимай самостоятельно, без согласования каждой стадии.

После сборки проверь весь экспорт, включая переходы, текст, разрешение UI при zoom и звук, если он входит в выбранную версию. Технические проверки дополни собственной оценкой по тем же критериям. Сохрани финальный ролик, три ключевых кадра и короткую заметку: какой исходный код проверен, что подтверждено просмотром и что осталось ограничением.
