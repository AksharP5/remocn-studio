# Holds and secondary motion

A hold gives the viewer time to understand a state. A completed element may remain
still for the entire reading window. Neither a focal subject nor a background
needs residual motion solely because the entrance has finished.

## Diagnose the interval

Identify what should happen: read the phrase, inspect a result, wait for a visible
process, experience an environment, or prepare for an accent. If the interval feels
empty, inspect the message and duration first. A missing result or wrong crop is
not repaired by adding drift.

Secondary motion belongs to the depicted behavior: fabric can settle after its
support, particles can continue through an impact, footage has its own action.
A rigid UI can settle as one unit. Continuous background motion is appropriate
when it establishes the environment; compare its attention demand with the subject.

## Numeric and repeated motion

Animate a count when accumulation or change is the message. Show the complete
number when the value itself is the message. Keep its final value readable and
use an actual value, not an invented metric.

An emphasis event can resolve into stillness. A loading indicator can loop while
a process is pending. Mechanical cycles may repeat exactly; organic motion can
use varied phases when that matches the subject. Seed any randomness so seeking
and rendering the same frame produce the same result.

## Verification

A sampled static run is evidence of unchanged samples, not proof of a stalled film.
Compare it with the promised behavior. Attach `keeps_moving` only to a specific
interval that should continuously move; a reading hold should not receive that
assertion. Preserve checks for an explicitly promised action that never happens.

When unwanted scale drift makes text unstable, remove the unnecessary movement
before adding rendering workarounds. For a required text move, consult the technical
text-rendering observations in `video-lessons` and inspect consecutive frames.
